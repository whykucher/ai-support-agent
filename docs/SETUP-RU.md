копировать целиком. Windows + PowerShell.

## Часть 1. Из чего состоит проект

Три части, которые работают вместе:

| Что | Где лежит | Простыми словами |
|---|---|---|
| Мозг | `app/` | Python-сервер: ищет ответ в документах, зовёт ИИ, считает «горячесть» клиента |
| Лицо | `web/` | Витрина-пример, виджет чата и панель управления |
| Знания | `knowledge/` | Обычный текстовый файл — всё, что бот знает о компании |
| Автоматизация | `n8n/` | Готовый сценарий n8n: куда отправлять горячие лиды |

Главное, что нужно понять: **бот отвечает только тем, что лежит в
`knowledge/`.** Хочешь переделать под другого клиента — меняешь этот файл, а не
код.

Сейчас проект работает в режиме `demo`: без ключей и без оплаты. Отвечает не
настоящий ИИ, а поиск по документам. Для портфолио этого достаточно, и это
плюс — демка не сломается от того, что кончились деньги на API.

## Часть 3. Выложить в интернет (бесплатно) — СДЕЛАНО

> Уже задеплоено: **https://ai-support-agent-jett.onrender.com**
> Панель управления: `/admin`. Пароль там не пишем — он лежит в Render:
> сервис `ai-support-agent` → вкладка **Environment** → переменная `ADMIN_TOKEN`.
> Сервис в Render называется `ai-support-agent`, регион Frankfurt, тариф Free.
>
> Ниже — как это было сделано, если понадобится повторить для клиента.

Кликабельная ссылка работает в разы лучше скриншотов. Клиент нажимает, пишет
боту, убеждается сам.

Проще всего — **Render**. В проекте уже лежит `render.yaml`, поэтому настраивать
почти нечего.

1. Зайди на <https://render.com> → **Get Started** → войти через GitHub.
2. **New** → **Blueprint**.
3. Выбери репозиторий `ai-support-agent`. Render сам найдёт `render.yaml`.
4. Он спросит значение **ADMIN_TOKEN** — это пароль от `/admin`. Придумай свой,
   например `MojSekretniyKluch2026`, и **запиши его**.
5. **Apply**. Первая сборка идёт 3–5 минут.

Готово. Ссылка будет вида `https://ai-support-agent-xxxx.onrender.com` — её и
даёшь клиентам. Панель управления там же, `/admin`, пароль — тот, что ты придумал
на шаге 4.

**Про бесплатный тариф, чтобы не удивляться:**

- Через 15 минут без посетителей сервис засыпает. Следующий заход грузится
  ~50 секунд. Перед созвоном с клиентом открой ссылку заранее, чтобы разбудить.
- Диска нет, база стирается при перезапуске. Поэтому в `render.yaml` включён
  `SEED_ON_START=true` — при старте панель сама заполняется примерами, и клиент
  никогда не увидит пустые нули.

Альтернативы, если Render не понравится: **Railway** (быстрее, ~$5/мес после
пробного периода) или **Fly.io** (есть бесплатный лимит, но настраивать сложнее).

## Часть 6. Подключить настоящий ИИ (по желанию, платно)

Демо-режим отлично работает для портфолио. Настоящая модель нужна, когда делаешь
проект живому клиенту, или если хочешь показать «как оно с Claude» на созвоне.

1. Получи ключ: <https://console.anthropic.com> (Claude) или
   <https://platform.openai.com> (GPT). Пополни баланс на минимум — $5 хватит
   надолго, один ответ стоит доли цента.
2. Открой файл `.env` в папке проекта Блокнотом и поменяй:

```ini
LLM_PROVIDER=anthropic
ANTHROPIC_API_KEY=sk-ant-вставь-сюда-свой-ключ
```

3. Перезапусти сервер.

Для более умного поиска можно добавить ещё и ключ OpenAI в `OPENAI_API_KEY` —
тогда включатся эмбеддинги. Без него поиск работает по ключевым словам, что тоже
нормально.

**На Render** ключ вставляется не в файл, а в веб-интерфейсе: сервис →
**Environment** → **Add Environment Variable**.

> Ключ — это доступ к твоим деньгам. Никогда не отправляй его на GitHub и не
> показывай в скриншотах.

## Часть 7. Показать доставку лидов без Docker

Самый быстрый способ доказать клиенту, что лиды реально уходят наружу, — не
поднимать n8n, а запустить встроенный приёмник. Он проверяет подпись запроса и
печатает каждый лид в терминал.

**Окно 1** — приёмник:

```powershell
cd "C:\Users\whykucher\Новая папка (4)\ai-support-agent"
$env:N8N_WEBHOOK_SECRET = "demo-signing-secret"
.\.venv\Scripts\python.exe -m scripts.fake_n8n
```

**Окно 2** — сервер, который знает, куда слать:

```powershell
cd "C:\Users\whykucher\Новая папка (4)\ai-support-agent"
$env:N8N_WEBHOOK_URL = "http://127.0.0.1:5999/webhook/lead-intake"
$env:N8N_WEBHOOK_SECRET = "demo-signing-secret"
.\.venv\Scripts\python.exe -m uvicorn app.main:app --port 8010
```

Оставь лид в чате — в первом окне сразу появится карточка с пометкой
`signature: verified`, а в панели `/admin` статус станет зелёным `sent`. Вот это
и стоит показывать на созвоне.

Если приёмник не запущен, в панели будет серый `n8n off`. Это не ошибка, а
честная пометка «интеграция не подключена» — лид всё равно сохранён, и кнопка
**Retry n8n** дошлёт его позже.

## Часть 8. Переделать под клиента

Три шага, код трогать не надо:

**1. Знания.** Положи документы клиента в `knowledge/<имя-сайта>/` — папка первого уровня и есть отдельный сайт. Например `knowledge/acme/faq.md`. Внутри —
FAQ, условия доставки, описание услуг. Формат — обычный текст с заголовками:

```markdown
# Доставка

Отправляем по России за 2–5 дней, стоимость 350 ₽...

# Возврат

14 дней с момента получения...
```

Один заголовок — одна тема. Именно по заголовкам работает поиск. Потом нажми
**Reindex** в панели `/admin`.

**2. Название и цвет.** В `.env`:

```ini
COMPANY_NAME=Название клиента
AGENT_NAME=Имя бота
```

**3. Установка на сайт клиента.** Одна строчка в шаблон сайта — работает на
Shopify, WordPress, Tilda, Webflow, где угодно:

```html
<script src="https://твой-адрес.onrender.com/static/widget.js"
        data-api="https://твой-адрес.onrender.com"
        data-lang="ru"
        data-site="acme"
        data-title="Поддержка Acme"
        data-agent="Аня"
        data-accent="#2563eb"
        defer></script>
```

`data-accent` — цвет виджета под фирменный стиль клиента. Цвет текста на кнопках
виджет считает сам по яркости фона, поэтому светлый акцент не даст белых букв на
жёлтом.

`data-lang="ru"` переводит сам интерфейс виджета — подсказку в поле ввода, форму
контактов, кнопки. Без него ассистент будет отвечать по-русски внутри английской
обёртки, и это выглядит как недоделка. Убери атрибут для английского клиента.

`data-site` — имя папки в `knowledge/`. Один сервер тянет сколько угодно
клиентов: у каждого своя база знаний, свои диалоги и свои лиды.

## Часть 8б. Русская сторона

Русский сайт живёт на `/ru` и это **отдельный сайт**, а не переключатель языка:
свои услуги, свои цены в рублях, свои три демо-бизнеса («Полдень», «Лоскут»,
«Ступень»). Английское портфолио подписано Nikita Denisov, русское — Леонид
Денисов.

Почему не перевод. Русское агентство, которое ведёт Google Ads и берёт деньги в
фунтах, читается как машинный перевод чужого бизнеса. Поэтому в русских
документах Яндекс.Директ и VK, СДЭК и ЮKassa, рассрочка Тинькофф и налоговый
вычет — то, о чём реально спрашивают.

Что пришлось сделать в поиске, кроме перевода текстов:

- Кириллица в токенизаторе. Без неё русский запрос распадался в пустой список и
  бот на любой вопрос отвечал «не знаю» — выглядит как дыра в базе знаний, а
  дыра была в регулярке.
- `ё` сводится к `е`. Половина людей пишет «счет», половина «счёт».
- Отсечение окончаний: «доставка», «доставки», «доставку» — одно слово.
- Там, где форма глагола до существительного не дотягивается («отчитываетесь»
  против «отчётность»), правится документ, а не поиск. В разделе просто стоит
  тот вопрос, который человек задаёт.

Проверить, что всё это работает, можно одной командой — она задаёт каждому
бизнесу его же вопросы с его страницы:

```bash
python scripts/smoke_test.py
```

Добавить ещё один русский бизнес — три шага и ни строчки кода в шаблонах:
папка в `knowledge/`, запись в `SITES` в `app/config.py` с `"lang": "ru"`, и
запись в `PAGES` в `app/sites.py`. Переключатель отраслей на `/ru` подхватит его
сам.

## Часть 9. Если что-то сломалось

**`python не является внутренней или внешней командой`**
Python не установлен или не в PATH. Поставь с <https://python.org>, при
установке обязательно отметь галочку **Add Python to PATH**.

**`error while attempting to bind on address ... 8000`**
Порт занят другой программой. Запусти на другом: `--port 8010`.

**Бот отвечает «I do not have that in the knowledge base»**
База не проиндексирована. Выполни:
```powershell
.\.venv\Scripts\python.exe -m scripts.ingest --no-embed
```

**Панель `/admin` пишет «Error: Invalid admin token»**
Пароль в поле сверху не совпадает с `ADMIN_TOKEN`. Локально — `demo-admin-token`,
на Render — тот, что ты придумал при деплое.

**Лиды висят в `pending`**
Это нормально, пока не подключён n8n. После подключения нажми **Retry n8n** —
все накопленные отправятся заново.

**Хочу проверить, что вообще всё цело**
```powershell
.\.venv\Scripts\python.exe -m scripts.smoke_test
```
Должно быть `20/20 checks passed`. Если нет — в выводе видно, что именно упало.

**На Render сборка упала**
Открой вкладку **Logs** у сервиса. Чаще всего дело в том, что забыл ввести
`ADMIN_TOKEN` на шаге 4.
