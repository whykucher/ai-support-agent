# Vercel — что работает, а что нет

**Живой адрес:** <https://ai-support-agent-lime.vercel.app>

Бесплатно, карту не просит, деплой запускается сам на каждый пуш в `main` —
руками в дашборд лазить не надо, в отличие от Render.

## Почему ушли с Render

Бесплатный Render усыпляет сервис через 15 минут тишины, и следующий
посетитель ждёт около 50 секунд на пустой странице. Для портфолио, которое
открывают по ссылке из отклика, это и есть всё первое впечатление.

Функции Vercel так не спят. Замеренное на живом сайте: сервер отвечает за
**5 мс**, полный круг из браузера — **248 мс**. Холодный старт (первый заход
после долгого простоя) я не замерял, но там поднимается импорт FastAPI и сборка
индекса из 63 разделов — это секунды, не пятьдесят.

## Чего этот деплой не умеет

**База не переживает перезапуск.** У функции Vercel файловая система только для
чтения, кроме `/tmp`, а `/tmp` принадлежит одному инстансу и умирает вместе с
ним.

Что из этого следует:

| | |
|---|---|
| Поиск и чат | работают полностью — индекс пересобирается при холодном старте |
| Демо-бизнесы, лаборатория, виджет | работают |
| Пойманная заявка | видна только тому инстансу, который её принял |
| Лента запусков на главной | показывает не «что сделало приложение», а «что сделал этот инстанс» |

Последнее важнее, чем кажется: на этом построено обещание страницы — ничего не
утверждается без записи в журнале.

**Чинится внешней базой.** Turso бесплатный и говорит по протоколу SQLite, так
что менять придётся немного. Пока не сделано.

## Две ошибки, на которые я напоролся

Обе теперь закрыты тестами, но знать полезно.

**1. Пустые переменные окружения.** На импорте Vercel читает `.env.example` и
создаёт все найденные ключи с **пустым значением**. `os.getenv` подставляет
дефолт только когда ключа нет, а не когда он пустой. Приложение стартовало с
`PORT=""`, `int("")` падал прямо на импорте модуля — функция умирала до первой
строки кода, наружу это выглядело как `FUNCTION_INVOCATION_FAILED`.

Починено в `app/config.py`: пустая переменная теперь значит «не задана».

**2. `/api/` — это папка Vercel.** Сначала конфиг использовал современную форму
`functions` + `rewrites`, и всё отдавало 404. Vercel разбирает свою папку `api/`
как файловые маршруты **до** того, как срабатывают rewrites, а у приложения свои
`/api/health`, `/api/chat`, `/api/runs` из FastAPI — они искались как
`api/health.py` и не находились.

Починено переходом на `builds` + `routes`: `routes` матчатся раньше файлового
слоя, и один catch-all отдаёт весь трафик приложению.

## Пароль к админке

Задан в переменных окружения проекта как `ADMIN_TOKEN`. В репозитории его нет и
быть не должно: дефолт `demo-admin-token` лежит в открытом коде, и с ним админка
с заявками и перепиской была бы закрыта общеизвестным паролем.

Поменять: Vercel → Settings → Environment Variables → `ADMIN_TOKEN` → Redeploy.

## Как обновлять

```bash
git push
```

Всё. Vercel соберёт сам.

## Если надо откатиться

Vercel → Deployments → нужный → **Promote to Production**.

Render (`render.yaml`) и Fly (`fly.toml`) остаются в репозитории рабочими. Не
сноси Render, пока не убедишься, что Vercel устраивает.
